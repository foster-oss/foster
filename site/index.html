Check your own project

Foster reads your lockfile and tells you which dependencies are orphaned, which have security holes with no fix, and which have a published drop-in security patch you can switch to in one command.

npx foster-oss scan          # what in my lockfile is orphaned or unpatched?
npx foster-oss fix           # switch to published drop-in patches (edits package.json)
npx foster-oss check ip@2.0.1

How this is measured

Packages come from the ecosyste.ms critical set: the top packages per registry by downloads and dependent repositories. Dead: repository archived, deprecated by the registry, or issues and pull requests opened in the past year with none closed or merged and no push or release. Dormant: no release and no push for over a year. Unknown: no linked repository. An "advisory with no fix" is a published security advisory for which no patched version exists. Full rules in METHODOLOGY.md. Download the data as JSON or CSV.

These are signals, not verdicts. A small package can be finished rather than abandoned. A dormant package only becomes urgent when it has a security problem nobody can fix: that is what Foster is for.
