Foster · The Orphan Index

The software everyone depends on, that nobody maintains.

We checked the most depended-on open source packages in six ecosystems (npm, PyPI, Cargo, Go, RubyGems and Packagist) and asked a simple question: is anyone still looking after them? This index updates weekly from public data.

Before your agent installs anything

Coding agents run npm install and pip install on their own. Foster guard checks every package a command would install, before it runs, and blocks:

  • known malware (OSV and the OpenSSF malicious-packages database),
  • names that don't exist, which anyone can register ("slopsquatting"),
  • vulnerabilities no release fixes, with maintained alternatives.

It asks about look-alikes of popular packages and brand-new packages that run install scripts, and reads what a command really installs: lockfiles (npm ci), package.json, monorepo workspaces, overrides, aliases, npx and corepack. Six ecosystems, no account, and it fails open if the network is down.

# an AI agent wants to run:
$ npm install lodahs react-pdf-renderer-utils request

Foster guard blocked this install:
- lodahs is known malware (MAL-2025-25502: Malicious code
  in lodahs). Do not install it.
- react-pdf-renderer-utils does not exist on the registry.
  It may be a hallucinated name; attackers register such names.
- request has security advisories that no release fixes;
  maintenance: dead. Alternatives: fetch, ofetch, ky

# lodahs was picked as a made-up typo for this demo.
# It turned out to be real, reported malware.

Check your own project

Foster reads your lockfile and tells you which dependencies are malware, orphaned, or have security holes with no fix, which direct dependency brings each one in, who to fund, and which have a published drop-in security patch you can switch to in one command.

npx foster-oss guard -- npm install some-package   # check an install before it runs
npx foster-oss scan          # what in my lockfile is orphaned or unpatched?
npx foster-oss fund          # which at-risk dependencies I rely on, and who to sponsor
npx foster-oss fix           # switch to published drop-in patches (edits package.json)
npx foster-oss check ip@2.0.1

Also as a GitHub Action that checks only what a pull request adds, with SARIF for the Security tab.

How this is measured

Packages come from the ecosyste.ms critical set: the top packages per registry by downloads and dependent repositories. Dead: repository archived, deprecated by the registry, or issues and pull requests opened in the past year with none closed or merged and no push or release. Dormant: no release and no push for over a year. Unknown: no linked repository. An "advisory with no fix" is a published security advisory for which no patched version exists. Full rules in METHODOLOGY.md. Download the data as JSON or CSV.

These are signals, not verdicts. A small package can be finished rather than abandoned. A dormant package only becomes urgent when it has a security problem nobody can fix: that is what Foster is for.
